# D29 — บัญชีผู้ดูแลสถานพักพิง ข้อมูลกลาง QR และภาษี

คำขอ 13 ต.ค. 2026 ต่อยอดจาก D28 ใช้ Supabase Free และ Vercel Hobby งบเพิ่ม 0 บาท บัญชีเป็นของจริง ส่วนสถานที่ เลขทะเบียน สถานะสัตว์ ยอดบริจาค และการชำระเงินเป็นข้อมูลทดลอง

## สองส่วนของเว็บ

1. **ผู้ใช้ทั่วไป**: ดูสถานที่บนแผนที่/ค้นหา ดูสัตว์หาบ้าน ขอรับเลี้ยงหรือส่งสัตว์เข้าดูแล ส่งข้อความขอติดต่อ และทดลองบริจาค ไม่แก้สถานที่คนอื่น
2. **ผู้ดูแลสถานพักพิง**: หลังล็อกอิน เปิดศูนย์จัดการ สร้างสถานที่และแก้ของตัวเอง เลือกมูลนิธิสาธิต/สถานพักพิง/ผู้ดูแลอิสระ เพิ่มรูป ปักหมุด เลือกเขตในกรุงเทพฯ ระบุเวลา เงื่อนไข ความจุ สัตว์ที่รับ เสบียง ความต้องการบริจาค และสัตว์หาบ้าน

บัญชีเดียวใช้ส่วนทั่วไปได้ด้วย การเลือกบทบาทผู้ดูแลไม่ใช่สิทธิ์ admin และไม่ใช่การยืนยันตัวตน

การสร้าง แก้ อัปโหลดรูป และเผยแพร่ต้อง Login Google หรืออีเมลจริงก่อน โหมด Demo และเลข Run ไม่ให้สิทธิ์แก้ข้อมูลกลาง API ตรวจ `getUser()` และ RLS ตรวจ `auth.uid()` ซ้ำ ไม่มีบัญชีจำลองผ่านปุ่ม Login

## วงจรข้อมูลและกฎส่วนกลาง

- สถานะ `draft` → `published` / `paused` → `archived` ร่างและเก็บถาวรเห็นเฉพาะเจ้าของ เผยแพร่แล้วทุกคนอ่านได้ พักการรับยังปรากฏพร้อมสถานะปิดรับ
- เก็บในตารางกลาง Supabase ไม่ใช่ localStorage ประจำ Run ไม่ใช้หน่วยความจำของ Vercel เป็นฐานข้อมูล หากฐานข้อมูลยังไม่พร้อม ต้องบอกตามจริงและไม่อ้างว่าเผยแพร่ให้คนอื่นแล้ว
- ID สถานที่และตำแหน่งคงเดิมขณะอัปเดต ไม่สุ่มหมุดใหม่ตาม Run รหัส `DEMO-REG-...` ที่สร้างฝั่งฐานข้อมูลเป็นเพียง ID ของ record ไม่ใช่เลขทะเบียนมูลนิธิ
- เมื่อเลือกประเภท “มูลนิธิ” ต้องกรอก `payload.registrationNumber` ก่อนบันทึกหรืออัปเดต บันทึกเป็นข้อมูลจำลองใน JSONB และแสดงต่อสาธารณะหลังเผยแพร่เท่านั้น ระบบตรวจว่ากรอกแล้ว แต่ไม่ตรวจสอบกับหน่วยงานและไม่รับรองการจดทะเบียน/สิทธิ์ภาษี สถานที่ประเภทอื่นไม่บังคับช่องนี้
- record รุ่นเก่าที่ไม่มี `registrationNumber` ยังอ่านและแสดงได้; เมื่อเจ้าของแก้ record มูลนิธิจะต้องกรอกเลขก่อนบันทึก ไม่มี schema migration เพิ่มเพราะใช้ field ใน JSONB เดิม
- ใช้ RLS: คนทั่วไปอ่านเฉพาะ published/paused เจ้าของอ่านและแก้ของตัวเองเท่านั้น API ตรวจผู้ใช้จาก Supabase ไม่รับ owner ID จาก client ไม่ใช้ service role
- แต่ละครั้งส่ง version เดิมมาด้วย หากข้อมูลเปลี่ยนจากอีกแท็บต้องแจ้ง conflict ไม่เขียนทับเงียบ เก็บวันที่ปรับปรุงและกิจกรรมเปลี่ยนสถานะ
- ตรวจความจุเป็นจำนวนเต็ม 1–1000, จำนวนดูแล 0–ความจุ, เสบียง 0–365 วัน, หมุดในขอบแผนที่กรุงเทพฯ รูปต้อง JPEG/PNG/WebP ที่ resize ในเว็บ ปฏิเสธ SVG/HTML ข้อความมีเพดานความยาว
- สถานที่ที่เผยแพร่ร่วมกับข้อมูลเดิมในแผนที่/ตัวกรอง/Smart Load Balancer ใช้กฎความจุเดียวกัน รูป หมุด และหน้า detail อ้าง ID เดียวกัน แสดงเวลาข้อมูลล่าสุด รีเฟรชส่วนกลางขณะหน้าเปิด/กลับมาจากแท็บอื่น
- คำขอติดต่อเห็นเฉพาะผู้ส่งและเจ้าของสถานที่ ไม่เผยแพร่อีเมลหรือข้อความส่วนตัวสู่ directory การขอรับเลี้ยงไม่เป็นการอนุมัติอัตโนมัติ
- เลขจดทะเบียนสาธิตและตราทดลองไม่รับรองความปลอดภัย การจดทะเบียนจริง หรือสิทธิ์ภาษี
- รูปเก็บใน bucket ส่วนตัว `community-shelters` จำกัด 160,000 bytes/ไฟล์ รูปที่ยังไม่แนบใน payload เผยแพร่ยังเป็นส่วนตัว รูปสาธารณะมี signed URL อายุ 15 นาที URL ที่ออกไปอาจใช้ได้จนหมดอายุเมื่อเก็บเข้าคลัง เก็บ URL เดิมจนใกล้หมดอายุเพื่อไม่ให้รูปกะพริบ
- จำกัดการเขียนตามบัญชี 30 ครั้ง/นาที, 500 ครั้ง/วัน และ 3,000 ครั้ง/วันต่อ instance แบบ best effort ไม่ใช้โควตา Login ของ IP ห้องเรียนกับการแก้บ้านพัก
- ลบบัญชีจะลบรูปผ่าน Storage API ก่อนลบ Auth user และ records ที่ผูกด้วย cascade ไม่ใช้ SQL ลบแถว Storage โดยตรง

## เส้นทางและวิธีเปิดใช้

| เส้นทาง | วิธีเข้า / สิ่งที่ทำได้ |
|---|---|
| `/` | กล่องเลือกพื้นที่ใต้ฉากสัตว์: คนรักสัตว์หรือผู้ดูแล |
| `/account` | เปลี่ยนบทบาทในบัญชีจริง บทบาทไม่ใช่สิทธิ์ admin |
| `/shelter/manage` | Login → เพิ่มบ้านพัก → กรอกข้อมูล → บันทึกร่าง → แนบรูป → ปักหมุด → ยืนยันเผยแพร่ → เผยแพร่ |
| `/shelters` | Directory กลาง ไม่ต้อง Login ค้นชื่อ/เขต/ประเภทและกดหมุด/รายละเอียด |
| `/shelters/[id]` | รูป ความจุ เสบียง รายชื่อ/พันธุ์สัตว์ หาบ้าน/ได้บ้านแล้ว แพ็กเกจ และฝากข้อความหลัง Login |
| `/nearby` | บ้านพักร่วมกับข้อมูลเดิม ใช้ Smart Load Balancer และ popup ชุดเดียวกัน |
| `/donate` | ผู้รับ → ของ → ตรวจทาน → QR → เปิดรูป/สแกน → ติ๊กเข้าใจ → ฉันชำระเงินแล้ว (ทดลอง) |
| `/demo/qr` | สุ่มจาก 57 ไฟล์ทุกครั้งฝั่ง server ไม่ล็อคต่อ QR ข้ามภาพเดิมทันทีตาม hash |
| `/donation-tax` | กฎภาษี แหล่งข้อมูล คำนวณสมมติ และพิมพ์สรุปส่วนตัวพร้อม watermark |

หน้าค้นหาอ่านข้อมูลใหม่ทุก 15 วินาทีเมื่อแท็บเปิด รวมทั้งเมื่อกลับเข้าแท็บ กดรีเฟรชได้ทันที Background refresh ไม่เขียนทับฟอร์ม หาก version เก่า คืน 409 และให้โหลดใหม่

## ตั้งค่าฐานข้อมูล / Login

1. Supabase Free โปรเจกต์ Cozypet ที่ Singapore ใช้ publishable key ฝั่ง server
2. ตั้ง `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SITE_URL` ใน Vercel ไม่ใส่ค่าใน Git
3. Migration history จริงตรงกับชื่อไฟล์ใน repo: `20261012193713_cozypet_initial_accounts.sql` → `20261013085213_cozypet_shared_shelters.sql` → `20261013214254_cozypet_photo_publication.sql` (applied แล้ว ไม่รัน SQL ซ้ำในโปรเจกต์นี้; โปรเจกต์ใหม่รันตามลำดับ)
4. Google Cloud Web application: origin `https://cozypet-iota.vercel.app`, redirect URI ตาม Supabase `/auth/v1/callback`
5. Supabase Sign In / Providers → Google → Client ID/Secret และ Enable; Skip nonce checks และ Allow users without an email ปิด
6. URL Configuration: Site URL `https://cozypet-iota.vercel.app`, Redirect URLs `https://cozypet-iota.vercel.app/auth/callback**`
7. ปุ่ม Google ตรวจ configuration จริงจาก `/auth/v1/settings` ไม่เปิดเพียงเพราะมี env ไม่ฝัง Client Secret อีเมลยังใช้ confirmation และจำกัดตาม Supabase หากไม่ได้ตั้ง SMTP ให้ใช้ Google เป็นช่องทางหลักของห้องเรียน
8. ไม่ใช้ Supabase OAuth Server สำหรับรับ Google Login ไม่เปิด billing/Free Trial ที่ผูกบัตร

ตรวจ project เป็น `free`, Google/email เปิดจริง และ migrations applied การเข้าสู่บัญชี Google ครั้งแรกต้องตรวจจากผู้ใช้จริง ไม่ถือว่า env/API 200 เป็นหลักฐาน Login สำเร็จ

Advisors พบ warning ของ RPC เดิม `delete_my_account()` แบบ SECURITY DEFINER ที่เปิดเฉพาะ authenticated ใช้ `auth.uid()` เท่านั้นและไม่มี target parameter เป็นฟังก์ชันลบบัญชีตัวเองที่ตั้งใจให้เรียก ดู [advisory](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) Index ใหม่ยังไม่มี usage ก่อนมี records ไม่ใช่เหตุให้ลบดัชนี

## QR ทดลอง

- ใช้ qrcode ที่ repo มีอยู่แล้ว QR เข้าหน้า `/demo/qr` ของเว็บ ไม่ใช่ PromptPay หรือ QR ธนาคาร ไม่เข้ารหัสเลขบัญชี ยอดเงินจริง หรือข้อมูลส่วนตัว
- QR แต่ละรอบมี nonce ใหม่ แต่ปลายทางสุ่มรูปทุกครั้งที่เปิด/กดเปลี่ยนรูป ไม่ผูกกับภาพคงที่ เก็บ manifest จากไฟล์ภาพทุกไฟล์ใน `C:\Users\Administrator\Pictures\Cat` และทำ asset สำหรับเว็บโดยไม่แก้ต้นฉบับ ภาพ GIF ใช้ภาพ preview เฟรมแรกเพื่อให้โหลดเบา
- เปิด QR ในเว็บได้โดยไม่ต้องหยิบมือถือสแกน จากนั้นปุ่ม **ฉันชำระเงินแล้ว (ทดลอง)** ใช้ยืนยันใน checkout เท่านั้น การเปิดหน้า QR หรือสุ่มรูปไม่ทำให้สถานะบริจาคสำเร็จ
- ยอด/ปลายทางผูกกับรายการที่กำลังตรวจทาน กันกดซ้ำ มีสถานะโหลดตามการสร้าง QR/โหลดภาพจริง ไม่รอปลอม ไม่เพิ่มช่องบัตร/โอนเงินจริง
- แพ็กเกจและการสมทบย่อยใช้ dialog เดียวกัน ยอดเครดิตเพิ่มหลังยืนยันทดลองสำเร็จเท่านั้น รายการเดิมก่อน D29 ยังคงอ่านได้

## ภาษีไทยและวิธีนำเสนอ

- บริจาคแก่สถานพักพิงไม่ได้ลดหย่อนทุกแห่ง ต้องเข้าเงื่อนไของค์การ/สถานสาธารณกุศลของกรมสรรพากร ไม่ตัดสินจากชื่อหรือเลขทะเบียนอย่างเดียว
- สำหรับการบริจาคที่ประกาศครอบคลุม ตั้งแต่ 1 ม.ค. 2569 ใช้ e-Donation เป็นหลักฐาน การซื้ออาหาร/ทรายไปให้เป็นการบริจาคสิ่งของ ไม่อ้างว่าเป็นเงินบริจาคที่ลดหย่อนบุคคลธรรมดาได้โดยอัตโนมัติ
- หน้า “บริจาคกับภาษี” อธิบายประเภทองค์กร ลิงก์ตรวจสอบ และตัวอย่างคำนวณที่ผู้ใช้ป้อนเอง ข้อมูลรายได้ไม่บันทึกลง server ยอดทดลองใน Cozypet ใช้ลดหย่อนจริงไม่ได้
- เอกสารดาวน์โหลด/พิมพ์ของเว็บเป็น “สรุปการบริจาคทดลอง” มี watermark ทดลอง ไม่มีตรากรมสรรพากร เลขผู้เสียภาษี หรืออ้างว่าเชื่อม e-Donation จริง
- หากทำเงินจริงในอนาคต ต้องตรวจหน่วยรับบริจาคและการเชื่อม e-Donation/คู่ค้ารับบริจาคก่อน แยกยอดซื้อสินค้า ค่าบริการ และเงินบริจาคที่เข้าเกณฑ์

## Motion / ส่งต่อ Claude

คงกรอบอุ้งเท้าตาม mascot, T.switch และ reduced motion ใช้ skeleton เฉพาะ request/image decode จริง ทัวร์อ่านได้แต่หยุดก่อนสมัคร บันทึก เผยแพร่ ส่งข้อความ และยืนยันทดลองทุกครั้ง ฉากวิดีโอ: เลือกผู้ดูแล → สร้างร่าง → รูป/ปักหมุด → เผยแพร่ → อีกบัญชีเห็นหมุด → QR เปิดรูปสุ่ม → ยืนยันทดลอง → สรุปบริจาค ไม่ถ่ายรหัสผ่าน/API key/ข้อมูลอีเมลจริง
