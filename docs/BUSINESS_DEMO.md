# Cozypet: โมเดลรายได้และฟีเจอร์ชุมชน (D26)

คำสั่งผู้ใช้ 12 ต.ค. 2026: เติม Commission/Dropship, โฆษณา, CSR และหน้าตามรายละเอียดเพื่อน พร้อมกติกาให้ Claude ทำ Motion/Video ต่อ เอกสารนี้ขยาย PROMPT.md D14 เฉพาะการจำลอง ไม่มี payment gateway, QR, เลขบัญชี, การโอนเงินจริง หรือการจัดส่งจริง

## 1. ผู้รับและขอบเขต

- สถานสงเคราะห์เดิม 20 ช่องยังคง ID/พิกัด/ช่องทางทางการ แยกจากมูลนิธิสมมติสำหรับงานธุรกิจ
- เพิ่ม `foundation-demo-001` บ้านอุ่นใจ (ดินแดง 95/100), `002` อุ้งเท้าพักใจ (จตุจักร 48/60), `003` เพื่อนสี่ขา (บางกะปิ 40/40) พิกัดคงที่ ข้อมูลชื่อ ความจุ อาหาร และภาพเป็นข้อมูลสาธิต
- ใช้ `isFictionalFoundation: true` และ `isRealOrganization: false` ให้ชัดเจน ห้ามเรียกว่าจดทะเบียนจริงหรือให้ดาว/ภาพรับของรับรองสถานที่จริง สถานสงเคราะห์จริงไม่เป็นผู้รับแพ็กเกจหรือเคสวิกฤต
- ผู้ดูแลรายบุคคลเดิมยังเป็นผู้รับได้ การแนะนำใช้ `rankDonationTargets` ใน balancer เดิม ไม่ให้ AI แต่งผลจัดอันดับ
- กรุงเทพฯ 50 เขตเท่านั้น ค้นชื่อไทยหรืออังกฤษได้ จังหวัดอื่นต้องแจ้งขอบเขตเดโม ห้ามเปลี่ยนพิกัดสถานที่ตามรอบค้นหา

## 3. เงินในคำสั่งซื้อและ Commission

1. เลือกผู้รับที่เข้าเงื่อนไข แพ็กเกจที่รองรับชนิดสัตว์ จำนวน 1–5 ยืนยันรับทราบว่าเป็นการจำลอง
2. บันทึกออเดอร์ `source: donor`, snapshot ราคาและเปอร์เซ็นต์ `settlementStage: received` เสมือนเงินเข้าระบบแล้ว
3. กด “จำลองการหักส่วนแบ่ง” → `commissioned` รายได้เว็บเพิ่มตามส่วนแบ่ง ส่วนต้นทุนรอส่งต่อ
4. กด “จำลองส่งออเดอร์และโอนต้นทุนให้คู่ค้า” → `partner_paid` พร้อม `fulfillmentStartedAt` จึงเริ่ม timeline จัดส่ง ไม่มีสต็อกหรือคลังสินค้าของ Cozypet
5. ตัวอย่าง 290 บาท: commission 29 ต้นทุนสินค้า/ค่าส่ง 261 บาท ไม่มีค่าธรรมเนียมเพิ่ม ผู้รับได้สินค้าในรายการครบ คำนวณเป็นสตางค์ ปัดเศษก่อนรวมให้ยอดตรง
6. ยกเลิกได้ก่อนคู่ค้าเริ่มส่ง ตัดยอดออกจากรายได้และเสบียงทันที ผลยกเลิกเป็นการจำลอง ไม่มีธุรกรรมคืนเงินจริง
7. คำสั่งเก่าที่ยังไม่มี settlementStage ใช้ flow เดิม ไม่ทำลายข้อมูลเก่า

## 4. Micro-Donation Tracker

- รับสมทบจำลอง 50 หรือ 100 บาท หลังติ๊กรับทราบ เลือกเคสได้ เงินของแต่ละมูลนิธิแยกกอง ห้ามย้ายไปเคสอื่นเอง
- ไม่มี seed ยอดเงินจริง ตัวเลขเริ่มจากกิจกรรมของผู้ทดลอง อัปเดตทันทีในเบราว์เซอร์และแท็บที่ใช้ localStorage เดียวกัน ไม่อ้าง real-time ข้ามผู้ใช้/เครื่อง
- ครบราคาแพ็กเกจอาหารของเคสนั้น สร้างออเดอร์จากยอดสะสมแบบ deterministic ID `pool-<foundation>-<number>` ไม่สร้างซ้ำเมื่อ refresh ยอดเศษคงไว้ซื้อแพ็กเกจถัดไป
- บันทึก source micro พร้อมการแบ่งเงิน/ต้นทุนจำลองจากราคาคู่ค้า เริ่มส่งตรงทันทีที่ครบยอด ดูออเดอร์ที่กองนี้ซื้อได้
- เครดิตผู้สมทบคำนวณจากเงินที่ตัวเองสมทบ ไม่ให้คะแนนซ้ำจากออเดอร์กองกลาง

## 5. โฆษณาและ CSR

- แบรนด์ Partner A/B/C เป็นสมมติ ราคาสมมติ: Home 7 วัน 700, Dashboard 7 วัน 500, Home 30 วัน 2,400 บาท
- เลือกบริบท cat/dog/all แสดงเฉพาะบริบทของหน้าหรือ mascot ที่เลือก ไม่เก็บ cookie โฆษณา ประวัติการท่องเว็บ หรือใช้ข้อมูลส่วนบุคคล
- พื้นที่เดียวกันมี active booking ได้หนึ่งรายการ ห้ามทับรายการเดิมโดยเงียบ ๆ ครบระยะจึงหยุดแสดง จอง/ยกเลิกอัปเดตแบนเนอร์ทันทีในเบราว์เซอร์เดียวกัน
- แคมเปญ CSR มี foundation, แพ็กเกจ, เป้าหมายจำนวน, ค่าโปรโมตแยกต่างหาก ค่าอาหาร = ราคาต่อแพ็กเกจ × เป้าหมายทั้งหมด
- ค่าอาหารส่งต่อคู่ค้าทั้งหมด ส่วนค่าโปรโมตนับเป็นรายได้ CSR ห้ามนับงบอาหารเป็นรายได้เว็บหรือหัก commission ซ้ำในออเดอร์ CSR
- หนึ่งสปอนเซอร์ต่อแคมเปญที่เปิด สร้างออเดอร์จำลองใน booking แสดงชื่อแบรนด์ ลิงก์ออเดอร์ และจำนวนแพ็กเกจที่ “ส่งถึงแล้ว” จาก timeline จริง
- ยกเลิก booking ทำให้ป้ายและออเดอร์ CSR หยุดมีผลต่อเสบียง/รายได้ ข้อมูลประวัติยังอยู่

## 6. กระดานความโปร่งใสและรีวิว

- อัลบั้มภาพรับของไม่สร้างภาพหลักฐานเอง ผู้ทดลองเลือกออเดอร์ Run ของตัวเองที่ส่งถึงแล้ว อัปโหลด JPG/PNG/WebP ไม่เกิน 5 MB ย่อใน browser ก่อนเก็บ ไม่เรียกบริการเสียเงิน
- เป็นบทบาทผู้ดูแลจำลอง ข้อความระบุว่าไม่ใช่หลักฐานการบริจาคจริง จำกัดหนึ่งภาพต่อออเดอร์/Run บันทึกซ้ำแทนรายการเดิม
- รีวิว 1–5 ดาว ข้อความ 5–500 ตัวอักษร หนึ่งรีวิวต่อสถานที่/Run แก้ไขได้ ต้องมีออเดอร์ถึงหรือยืนยันส่งต่อที่เกี่ยวข้องก่อน
- แสดงค่าเฉลี่ย จำนวนรีวิว และ Run ไม่มีป้ายรับรองปลอดภัยจากดาว ไม่มีชื่อผู้ใช้งานจริงหรือเบอร์โทร
- สถานสงเคราะห์จริงไม่รับภาพ/รีวิวใน flow ธุรกิจนี้

## 7. โปรไฟล์และสัญญา

- ประวัติและยอดต้องเป็นของ Run ปัจจุบันเท่านั้น ไม่รวมสปอนเซอร์หรือกองกลางเป็นยอดส่วนตัวซ้ำ
- “รับเลี้ยงแล้ว” นับเฉพาะ Handoff ที่มีผลยืนยันและชนิดคำขอเป็น adopt ไม่ถือคำขอ pending ว่ารับเลี้ยงแล้ว
- แต้มน้ำใจไม่มีมูลค่า ไม่มีผลรับรองบุคคล ใช้ daily cap เดิมและไม่เพิ่มแต้มจากการส่งฟอร์มรีวิว/รูป
- สัญญา A4 ข้อความทั่วไป มีช่องลงชื่อบนเอกสารเท่านั้น ใช้ Print/Save as PDF ไม่เก็บลายเซ็น เลขบัตร หรือที่อยู่จริง

## 8. ข้อมูลและความต่อเนื่อง

- `businessState` มี bookings, microDonations, reviews, receipts เก็บผ่าน storage adapter เป็น local-only ตาม browser/account namespace ของเดโม รีเซ็ต Demo ลบข้อมูลชุดนี้ด้วย ไม่แก้ schema Supabase ที่ใช้งานเดิม
- ออเดอร์ผู้บริจาคเดิมคง `donationOrders` ส่วนออเดอร์กองอาหารคำนวณจาก microDonations และออเดอร์ CSR อยู่ใน booking ใช้ hook `useDonationOrders` เพื่อแสดงชุดเดียวกัน ไม่เขียนซ้ำสามที่
- เมื่อพื้นที่จัดเก็บเต็มต้องแจ้ง ไม่เปลี่ยนหน้าและอ้างว่าบันทึกสำเร็จ ตรวจซ้ำใน handler เพื่อกันกดซ้ำ/เปลี่ยนตัวเลือก
- ทุกข้อความผ่าน i18n TH/EN ภาพใช้เครดิตเดิม ไม่เพิ่มบริการหรือค่าใช้จ่าย

## 9. Motion และ Video สำหรับ Claude

- ใช้ Motion LazyMotion/m + tokens เดิม แอนิเมชันเฉพาะ opacity/transform/filter คง reduced motion ไม่เติมเวลารอปลอม ปุ่มเงิน/สมทบเปลี่ยน record จริงในเดโม
- skeleton มีเฉพาะ hydration, route loading, image fetch/decode และระหว่างย่อรูปจริง
- data-tour: `micro-donation`, `crisis-cases`, `business-banner`, `business-money-flow`, `business-revenue`, `business-partners`, `transparency-board`, `community-reviews`, `profile-credit`
- autopilot ต้องหยุดก่อนปุ่มสมทบ จองโฆษณา สปอนเซอร์ แบ่งเงิน ส่งออเดอร์ อัปโหลด หรือบันทึกรีวิว ห้ามตั้ง data-tour-safe ให้ปุ่มเขียนข้อมูล
- ฉากวิดีโอแนะนำ: (1) 50+100 รวมกองอาหารและชื่อเคส (2) เคสอาหารใกล้หมด+หมุดเต็มแนะนำที่อื่น (3) เลือกแพ็กเกจ+290→29/261 (4) คู่ค้าส่งตรงและภาพรับของ (5) แบนเนอร์แบรนด์/CSR (6) Dashboard แยกรายได้และประวัติส่วนตัว
- หากต้องเตรียมข้อมูลสำหรับถ่ายวิดีโอ ให้ใช้ข้อมูลจำลองที่ผู้ใช้สร้างหรือ fixture แยกในงาน capture ต้องไม่ส่งแบบฟอร์มด้วย autopilot และไม่เปลี่ยนสถานะ production
- คำบนวิดีโอและรายงานต้องระบุยอดจำลอง ไม่ใช้ “ยอดบริจาคจริง”, “มูลนิธิจดทะเบียนจริง”, “AI ยืนยันปลอดภัย” หรืออ้างว่ามีการจัดส่งจริง
